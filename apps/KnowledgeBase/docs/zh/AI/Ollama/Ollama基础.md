Ollama 是一个用于本地部署大语言模型（LLM）的工具，它将模型下载、管理、推理、API 服务全部封装好，让开发者可以像使用 Docker 一样简单地本地运行 AI 模型；

它最大的目标就是：
- 一条命令运行模型
- 不需要自己配置 CUDA、Transformers、GGUF 等复杂环境
- 提供统一 API，方便开发

安装：

```
curl -fsSL https://ollama.com/install.sh | sh
```

### 查看模型

```
ollama list

# 示例输出
AME            ID              SIZE      MODIFIED
qwen3:latest    500a1f067a9f    5.2 GB    2 hours ago
llama3.2:3b     8fdf8f752f6e    2.0 GB    1 day ago
```

### 下载模型

从 Ollama 官方模型库下载指定模型到本地，下载完成后可全程离线使用

```
# 下载默认 latest 版本
ollama pull qwen3

# 下载指定参数量/功能版本的模型
ollama pull deepseek-r1:7b
ollama pull gemma3:4b-instruct-q4_K_M
```
### 运行模型

运行流程：
- **首次运行**：若本地未找到对应模型，会自动执行下载流程，下载完成后自动加载并进入对话界面。
- **后续运行**：直接从本地加载模型，加载速度取决于硬件性能（显存 / 内存读写速度）。
- **对话模式**：进入终端交互界面后，直接输入问题并回车即可获得模型回复，默认自动维护多轮对话上下文

```
ollama run qwen3

# 单行执行模式
ollama run qwen3 "用一句话解释什么是大语言模型"
```

在对话界面中，可通过内置指令执行常用操作：

- `/bye` 或快捷键 `Ctrl + D`：退出对话，终止当前模型进程。
- `/reset`：清空当前对话上下文，开启全新对话，不退出交互界面。
- `/help`：查看全部内置交互指令与参数说明。
- `/set parameter <参数名> <值>`：临时调整生成参数，例如 `/set parameter temperature 0.7`。
### 删除模型

删除本地指定的模型文件，释放磁盘存储空间

```
ollama rm qwen3
```


### 查看模型信息

会输出：

- 参数数量：模型的参数量级（如 7B、14B），直接决定模型能力上限与硬件资源占用。
- 上下文长度（Context Window）：模型单次可处理的最大 Token 数量，决定了对话记忆长度与可处理文本规模。
- License：模型对应的开源协议，界定商用、二次分发等使用权限边界。
- Template：模型对话的提示词模板，定义了用户输入、系统提示、模型回复的格式化拼接规则。
- System Prompt：模型内置的默认系统提示词，决定了模型的基础行为与角色设定。
- Modelfile：完整的模型配置文件内容，可导出后用于自定义模型。
- 量化方式：模型的量化精度（如 Q4_K_M、Q8_0），量化等级越低体积越小、运行速度越快，但生成效果会有轻微损耗。

```
ollama show qwen3
```
### 启动 API 服务

前台启动 Ollama 的 API 服务，对外提供标准 RESTful 接口，供应用程序、开发框架调用本地模型

```
ollama serve
```

默认监听：

```
http://localhost:11434
```

核心接口：包含 `/api/chat`（多轮对话）、`/api/generate`（文本生成）、`/api/tags`（列出本地模型）等，原生支持流式响应

### 配置文件

所有数据默认存储在用户目录下的隐藏文件夹 `.ollama` 中，不同系统路径略有差异：

| 系统               | 默认路径                        | 说明                        |
| ---------------- | --------------------------- | ------------------------- |
| macOS            | `~/.ollama`                 | 用户主目录下的隐藏文件夹              |
| Windows          | `C:\Users\<用户名>\.ollama`    | 即 `%USERPROFILE%\.ollama` |
| Linux（普通用户安装）    | `~/.ollama`                 | 手动启动服务时使用此路径              |
| Linux（官方脚本系统级安装） | `/usr/share/ollama/.ollama` | systemd 服务运行时的默认路径        |

可通过环境变量 `OLLAMA_MODELS` 自定义模型存储目录，迁移到非系统盘释放空间；

根目录 `.ollama` 下的文件结构大致如下：

```
.ollama/
├── models/                # 核心：模型存储目录（占99%以上磁盘空间）
│   ├── blobs/             # 二进制权重文件（实际模型数据）
│   └── manifests/         # 模型元数据清单（索引文件）
├── history                # 本地交互式对话历史记录
├── id_ed25519             # 私钥文件（用于私有仓库认证、模型签名）
├── id_ed25519.pub         # 公钥文件
└── logs/
    └── server.log         # Ollama 后台服务运行日志
```

核心目录：models/

这是 Ollama 最核心的存储目录，所有下载的模型都在这里管理，分为 `blobs` 和 `manifests` 两部分

（1）blobs/ —— 实际模型数据层：
- 是 Ollama 存储实际模型数据的核心目录，采用内容寻址的存储设计，目录内所有文件均以 `sha256-<哈希值>` 的格式命名，文件名本身就是对应文件内容的 SHA256 哈希校验值；
- 这里存放的不只是核心的 GGUF 模型权重文件，还包括模型的提示词模板、开源许可证、默认生成参数、系统提示词等所有配置内容，每一项内容都会作为独立的 blob 分层文件存储；
- 该目录最核心的特性是自动去重，同一系列的多个模型会共享内容完全一致的基础数据层，相同的 blob 文件只会在本地保留一份，能大幅节省磁盘空间；
- 执行删除模型操作时，也只会清理不再被任何模型引用的 blob 文件，仍在被其他模型使用的文件会完整保留；

（2）manifests/ —— 模型元数据清单：
- 负责存储所有模型的元数据清单，官方下载的模型都会存放在 `manifests/registry.ollama.ai/library/<模型名>/<标签>` 的路径下；
- 每一个模型标签都对应一个 JSON 格式的清单文件，记录对应模型由哪些 blob 数据层组合而成，其中包含每一层文件的哈希值、文件类型、文件大小，同时还会标注模型架构、运行参数等完整元数据；
- 使用的 `ollama list`、`ollama show` 等管理命令，读取的都是该目录下的清单信息，而非直接解析体积庞大的模型权重文件，以此保证管理操作的高效性

### 自定义模型

`Modelfile` 是 Ollama 的模型定义文件，类似 Docker 的 Dockerfile，通过指令声明模型的底座来源、系统提示、推理参数等配置

在本地新建一个无后缀的文件，命名为 `Modelfile`，写入以下内容：

```
# 声明底座模型：基于 qwen3 最新版本构建
FROM qwen3:latest

# 固化系统提示词：每轮对话自动注入，永久生效
SYSTEM """
你是一位拥有 20 年经验的软件架构师。

回答要求：
- 全部使用中文
- 优先给代码
- 每一步都解释原因
"""

# 模型推理超参数配置
PARAMETER temperature 0.2
PARAMETER num_ctx 32768
```

终端进入 `Modelfile` 所在的目录，执行创建命令：

```
ollama create my-qwen -f Modelfile
```

- `my-qwen`：自定义模型的名称，可自行修改，后续运行模型时使用该名称；
- `-f Modelfile`：指定配置文件路径；若不在当前目录，需填写完整绝对路径，例如 `-f D:\OllamaModels\Modelfile`；
