## ES Module

ES Module（简称 ESM）是ES6正式引入的官方标准模块系统，通过静态的 `import` 和 `export` 声明定义模块依赖与对外接口。它替代了早期社区提出的 CommonJS、AMD 等非标准方案，目前已成为浏览器、Node.js 等所有现代 JavaScript 环境的原生模块标准；

### 模块导出

`export` 必须出现在模块的顶层作用域，不能写在函数、条件语句、循环内部；导出的名称必须是静态确定的，不能动态生成。 这种设计是为了让引擎在代码执行前就能扫描到所有导出，支持静态分析，ESM 的导出分为命名导出和默认导出两类：

命名导出：每个命名导出都对应一个标识符，一个模块可以有任意多个命名导出：

```
// 声明时直接导出
export const PI = 3.14159;
export function add(a, b) {
  return a + b;
}

// 集中统一导出
export { PI, add as sum };
```

默认导出：一个模块最多只能有一个默认导出，对应 `default` 这个特殊的导出名。适合导出模块的核心功能，导入时可以自定义名称；

```
// 导出函数作为默认值
export default function log(message) {
  console.log(message);
}

// 也可以导出对象、值等
// export default { version: '1.0.0' };
```

### 模块导入

与导出对应，导入也有多种形式，同样遵循静态约束：

- 只能出现在模块顶层，不能嵌套在函数、条件中；
- `from` 后面的模块说明符（路径）必须是**字符串字面量**，不能是运行时计算的变量

命名导入：导入指定的命名导出，名称必须和导出名一致，可用 `as` 设置本地别名。

```
import { PI, add } from "./math.js";
// 导入并重命名
import { add as sum } from "./math.js";

console.log(PI); // 3.14159
sum(1, 2); // 3
```

默认导入：导入默认导出，本地名称完全由导入方自定义，不需要大括号。

```
import writeLog from "./logger.js";
writeLog("hello"); // 等效于调用 logger.js 的 default 函数
```

命名空间导入：用 `import * as` 将模块所有导出挂载到一个命名空间对象上，所有导出都作为该对象的属性。

```
import * as math from "./math.js";
math.add(1, 2); // 3
console.log(math.PI); // 3.14159
```

### 模块的解析

ESM 的加载过程是规范定义的三阶段模型，这也是它能支持静态分析和循环依赖的核心原因。

1. 解析阶段（Parse） 引擎加载模块的源码文本，解析成抽象语法树（AST），扫描所有 `import` 和 `export` 声明，构建模块依赖图。这个阶段不执行任何业务代码，只做依赖分析。
2. 实例化 / 链接阶段（Instantiate / Link） 为每个模块创建独立的作用域环境，为所有导出的绑定分配内存空间；同时将每个 `import` 指向对应模块的导出绑定，完成 “链接”。此时变量只是占位，还没有被赋值。
3. 求值阶段（Evaluate） 按照依赖关系深度优先执行模块的顶层代码，为导出的绑定赋值。被依赖的模块先执行，依赖方后执行。

模块依赖图允许浏览器和工具在执行前分析依赖、检查导出名称，并进行 tree shaking 等优化；

对比 CommonJS：CommonJS 是运行时加载，执行到 `require()` 时才去加载、解析、执行模块，依赖关系在运行时才能确定，无法做提前的静态优化

### 实时绑定

ESM 最核心的特性之一：导入的是导出变量的 “绑定引用”，而不是值的拷贝；

核心表现：

- 导出方修改导出的变量值，导入方会自动同步更新；
- 导入方不能给导入的绑定重新赋值（绑定本身是只读的），否则会抛出 TypeError；

```
// counter.js
export let count = 0;

export function increment() {
  count++;
}
```

```
// main.js
import { count, increment } from "./counter.js";

console.log(count); // 0
increment();
console.log(count); // 1

// count = 10; // TypeError，导入方不能给导入绑定赋值
```

### 模块缓存

ESM 有内置的模块缓存机制，核心规则：同一个模块加载器 + 同一个模块标识（路径 / URL），模块只会被实例化、执行一次，后续所有导入都共享缓存的同一个实例

```
// store.js
console.log("store evaluated");

// 无论在多少个模块里 import "./store.js"，顶层代码只会执行一次，所有导入方共享同一个store对象
export const store = {
  count: 0,
};
```

ESM 的模块缓存不是普通 JavaScript 对象，标准 ESM 没有提供任意删除缓存并重新执行模块的通用 API，无法像 CommonJS 那样操作 `require.cache`；

### 循环依赖

ESM 可以建立循环依赖，因为链接阶段先创建绑定，再执行模块；

```
// a.js
import { valueB } from "./b.js";

// 把读取逻辑放到函数里，不顶层执行
export function printValueB() {
  console.log(valueB); // 调用时才执行，此时 valueB 早已初始化
}

export const valueA = "A";
```

```
// b.js
import { valueA, printValueB } from "./a.js";
export const valueB = "B";

// 模块执行完后再调用函数
printValueB(); // "B"，正常输出
```

执行顺序：

1. 入口 b.js → 遇到 import a → 执行 a.js
2. a.js 执行完所有顶层代码，`valueA` 初始化完成
3. 回到 b.js，执行完剩余代码，`valueB` 初始化完成
4. 最后调用 `printValueB()`，此时两个变量都已初始化，不会报错

如果模块顶层代码在对方绑定初始化前就立即读取它，会触发 TDZ，抛出 ReferenceError

```
// a.js
import { valueB } from "./b.js";  // 第1行：导入 b 的 valueB
console.log(valueB);             // 第2行：立刻读取 valueB（报错行）
export const valueA = "A";       // 第3行：导出 valueA
```

```
// b.js
import { valueA } from "./a.js";  // 第1行：导入 a 的 valueA
export const valueB = "B";        // 第2行：导出 valueB
```


### 动态 import

`import(specifier)` 可以在运行时按需加载模块，返回一个 Promise；

核心特点

- 可以在函数、条件语句、循环等任意位置调用；
- 模块说明符可以由运行时计算（模板字符串、变量拼接等）；
- 返回 Promise，resolve 的值是模块的命名空间对象；
- 同样遵守模块缓存规则，重复导入相同模块只会执行一次。

```
async function loadEditor() {
  // 按需加载编辑器模块
  const module = await import("./editor.js");
  
  module.initialize(); // 访问命名导出
  module.default?.();   // 访问默认导出
}
```


### 模块顶层await

ES Module 顶层可以直接使用 `await`，不需要包裹在 async 函数中；

注意事项

- 会延迟所有依赖该模块的模块的执行，谨慎使用；
- 循环依赖中的异步求值会让执行顺序更难分析；
- 多个可并行的异步任务，建议先全部启动，再用 `Promise.all()` 等待，提升性能；

用于模块本身的初始化依赖异步操作的场景，比如加载配置、请求初始数据：

```
// config.js
const response = await fetch("/config.json");
export const config = await response.json();
```

```
// 依赖该模块的模块会自动等待其完成求值
import { config } from "./config.js";
console.log(config); // 能拿到完整的配置数据
```


### ESM 与 CommonJS 的差异

ESM 与 CommonJS 是 JavaScript 生态中两种主流模块系统，二者核心差异如下：

- 依赖分析方式
    - ESM：静态模块结构，import/export 必须在模块顶层且为字面量，可在代码执行前完成完整的依赖分析，支持 Tree Shaking 等编译时优化
    - CommonJS：`require()` 是运行时函数调用，依赖关系在代码执行过程中才能确定，无法提前做静态分析
- 适用环境
    - ESM：ECMAScript 官方标准，浏览器、Node.js、Deno 等所有现代 JS 环境原生支持
    - CommonJS：Node.js 传统社区模块机制，浏览器原生不支持，需打包工具转换
- 导出语义
    - ESM：导出的是变量的实时绑定引用，导入方是只读视图；导出方修改变量值，导入方会同步更新
    - CommonJS：导出的是 `module.exports` 在导出时的当前值快照；基本类型是值拷贝，引用类型是引用拷贝，导出方后续修改变量不会同步给已导入的模块
- 模块顶层 this 指向
    - ESM：模块顶层 `this` 为 `undefined`
    - CommonJS：模块顶层 `this` 指向 `module.exports` 对象
- 异步加载能力
    - ESM：支持动态 `import()`，返回 Promise，可实现按需、条件异步加载模块
    - CommonJS：`require()` 是同步 API，只能同步加载模块，原生不支持异步导入
- 顶层 await 支持
    - ESM：支持 Top-level await，可在模块顶层直接使用 `await` 做初始化
    - CommonJS：不支持顶层 await，异步初始化逻辑必须包裹在 async 函数中
