## Promise

Promise 是 ES6 引入的异步编程标准解决方案，它代表一个异步操作的最终完成（或失败）及其结果值。它统一了异步操作的状态管理、结果传递和错误传播方式，解决了传统回调嵌套过深形成的「回调地狱」问题，是现代 JavaScript 异步编程（async/await、fetch 等）的核心基石

### Promise 状态

Promise 有且仅有三种状态，状态流转是单向不可逆的：

- pending（待定）：初始状态，异步操作尚未完成，既没有兑现也没有拒绝
- fulfilled（已兑现）：操作成功完成，拥有一个最终结果值
- rejected（已拒绝）：操作失败，拥有一个拒绝原因（通常是 Error 对象）

### executor

传入 `new Promise(executor)` 的函数被称为 executor（执行器），它是 Promise 的执行入口，会在 Promise 构造时立即同步执行；

executor 的返回值会被忽略，不会影响 Promise 的状态；但是如果 executor 函数内部同步抛出异常，Promise 会自动变为 rejected 状态；

```
console.log(1);

const promise = new Promise((resolve) => {
  console.log(2); // executor 同步执行
  resolve(3);     // 标记为成功，then 回调进入微任务队列
});

console.log(4);

promise.then(console.log); // 同步代码执行完后，才执行微任务回调

// 输出顺序：1 → 2 → 4 → 3
```

### resolve 与 reject

`resolve` 和 `reject` 是 executor 接收的两个参数，用于控制 Promise 的状态，第一次有效的调用会锁定 Promise 的状态和结果，之后所有调用都会被静默忽略；

`resolve(value)`： 不只是简单地把 Promise 设为成功，它会对传入的 value 进行**解析**，根据 value 类型不同有不同行为：

- 普通值：Promise 直接变为 fulfilled，结果为该值；
- Promise：外层 Promise 会跟随该 Promise 的最终状态；
- thenable：会调用其 then 方法，跟随其最终结果；
- 自身：会以 TypeError 拒绝（循环引用）；

thenable 是指一个拥有 `then` 方法的普通对象，它符合 Promise 的接口约定。`resolve` 会像处理 Promise 一样执行它的 then 方法，兼容不同的 Promise 实现（如早期的 Q、bluebird 等）；

```
// 示例：resolve thenable 对象
const thenable = {
  then(resolve) {
    setTimeout(() => resolve("thenable 结果"), 500);
  }
};
Promise.resolve(thenable).then(console.log); // 500ms后打印 "thenable 结果"
```

`reject` 不会对传入的 `reason` 做任何解析，直接用该值作为拒绝原因。即使传入一个成功的 Promise，也会把这个 Promise 对象本身作为拒绝原因，而不会跟随它的状态；

```
const inner = Promise.resolve("done");

const outer = new Promise((resolve) => {
  resolve(inner);
});

outer.then(console.log); // "done"
```

### then /catch/finally

then(onFulfilled, onRejected)：用于注册 Promise 状态变更时的回调函数，是 Promise 最核心的方法。

- 第一个参数 `onFulfilled`：fulfilled 状态的回调，接收结果值；
- 第二个参数 `onRejected`：rejected 状态的回调，接收拒绝原因，可选；

```
promise.then(
  (value) => {
    console.log("fulfilled:", value);
  },
  (reason) => {
    console.log("rejected:", reason);
  },
);
```

`catch(onRejected)` 是 `then(undefined, onRejected)` 的语法糖，专门用于注册拒绝回调，只处理失败情况

```
// 两种写法完全等价
promise.then(undefined, err => console.log(err));
promise.catch(err => console.log(err));
```

`finally(onFinally)`用于注册无论成功失败都会执行的回调，通常用于资源清理（关闭加载动画、关闭数据库连接等）

核心特性：

1. 不接收参数：finally 回调不会接收到 Promise 的结果值或拒绝原因，它不知道操作是成功还是失败，只知道操作结束了。
2. 状态透传：正常情况下，finally 不会改变原 Promise 的状态和结果，会把原值原样向后传递。
3. 异常覆盖：如果 finally 中抛出异常，或者返回一个 rejected 的 Promise，那么整个链会以这个新的原因拒绝；

```
Promise.resolve(1)
  .finally(() => {
    console.log("清理资源");
    // 没有 return，或者 return 普通值，都不影响结果
  })
  .then(console.log); // 1，原值透传
```


### Promise 链式调用

因为 `then()`、`catch()`、`finally()` 都返回新的 Promise，所以可以形成链式调用，避免了传统的回调嵌套问题；

链式调用中，每一个处理函数的返回值，都会决定下一个 Promise 的状态：

- 返回普通值：新 Promise 变为 fulfilled，结果为该值；
- 返回 Promise 或 thenable：新 Promise 跟随其最终状态；
- 抛出异常：新 Promise 变为 rejected；
- 没有返回值：新 Promise 变为 fulfilled，结果为 `undefined`；

```
Promise.resolve(1)
  .then(value => value + 1)        // 返回普通值 2
  .then(value => Promise.resolve(value * 2)) // 返回 Promise，结果 4
  .then(console.log)               // 打印 4
  .catch(console.error);
```

错误会沿着 Promise 链向后传播，直到遇到最近的拒绝处理函数（`catch` 或 `then` 的第二个参数）。中间没有错误处理的 `then` 会被直接跳过

```
Promise.resolve()
  .then(() => {
    throw new Error("操作失败");
  })
  .then(() => {
    console.log("不会执行"); // 被跳过
  })
  .then(() => {
    console.log("也不会执行"); // 被跳过
  })
  .catch(error => {
    console.error(error.message); // "操作失败"，捕获到前面的错误
  });
```

### 值穿透

值穿透是 Promise 一个重要但容易被忽略的特性：如果 then () 的对应参数不是函数，那么这个回调会被忽略，对应状态的结果会继续向后传递：

- 缺少兑现处理函数时，兑现值继续向后传递；
- 缺少拒绝处理函数时，拒绝原因继续向后抛出；

本质：当 then 的参数不是函数时，相当于没有注册对应回调，Promise 的状态和值会原样传递给返回的新 Promise；

```
// 成功值穿透
Promise.resolve(1)
  .then(undefined)  // 不是函数，被忽略，值穿透
  .then("也不是函数") // 同样被忽略
  .then(value => value + 1)
  .then(console.log); // 2

// 失败值穿透
Promise.reject(new Error("failed"))
  .then("not a function") // 没有拒绝处理函数，错误继续穿透
  .catch(error => console.log(error.message)); // "failed"
```



### Promise静态方法

Promise.resolve(value)：快速创建一个已解析的 Promise。它会按照 `resolve` 的规则解析传入的值：

- 如果传入的本身就是 Promise，直接返回它；
- 如果传入 thenable，会解析它；
- 其他情况返回 fulfilled 状态的 Promise。

```
// 等价于 new Promise(resolve => resolve(123))
Promise.resolve(123).then(console.log); // 123

// 传入 Promise 直接返回原对象
const p = Promise.resolve(1);
console.log(Promise.resolve(p) === p); // true
```

Promise.reject(reason)：快速创建一个已拒绝的 Promise，直接用传入值作为拒绝原因，不做任何解析

```
// 等价于 new Promise((_, reject) => reject("出错了"))
Promise.reject("出错了").catch(console.log); // "出错了"
```

Promise.all(iterable)：并行执行多个 Promise，全部成功才成功，一个失败就立即失败。

行为规则：

- 输入一个可迭代对象（通常是数组），包含多个 Promise
- 全部都 fulfilled 时，返回的 Promise 才 fulfilled，结果是按输入顺序排列的结果数组
- 任意一个 rejected，返回的 Promise 立即 rejected，原因是第一个失败的原因
- 空可迭代对象，立即兑现为空数组

```
const p1 = Promise.resolve(10);
const p2 = new Promise(resolve => setTimeout(() => resolve(20), 100));
const p3 = Promise.resolve(30);

Promise.all([p1, p2, p3]).then(results => {
  console.log(results); // [10, 20, 30]，顺序和输入一致
});
```


Promise.allSettled(iterable)：等待所有 Promise 都结束（无论成功失败），返回每个的结果状态

行为规则：

- 永远不会 reject，只会 fulfilled
- 返回数组，每个元素是结果对象：
    - 成功：`{ status: 'fulfilled', value: 结果值 }`
    - 失败：`{ status: 'rejected', reason: 拒绝原因 }`

```
const success = Promise.resolve("成功");
const fail = Promise.reject(new Error("失败"));

Promise.allSettled([success, fail]).then(results => {
  console.log(results);
  // [
  //   { status: 'fulfilled', value: '成功' },
  //   { status: 'rejected', reason: Error: 失败 }
  // ]
});
```

 Promise.race(iterable)：竞速模式，采用第一个 settled 的 Promise 的状态和结果，谁先结束，就采用谁的结果，不管成功还是失败。

```
const fast = new Promise(resolve => setTimeout(() => resolve("快的"), 100));
const slow = new Promise(resolve => setTimeout(() => resolve("慢的"), 500));

Promise.race([fast, slow]).then(console.log); // "快的"
```

 Promise.any(iterable)：只要有一个成功就成功，全部失败才失败；行为规则：

- 第一个 fulfilled 的 Promise 出现时，返回的 Promise 就变为 fulfilled
- 所有 Promise 都 rejected 时，才会 rejected，原因是 `AggregateError` 对象，其 `errors` 属性包含所有拒绝原因
- 空可迭代对象也会以 AggregateError 拒绝

```
const fail1 = Promise.reject(new Error("错误1"));
const fail2 = Promise.reject(new Error("错误2"));
const success = Promise.resolve("成功了");

Promise.any([fail1, fail2, success]).then(console.log); // "成功了"
```
## async 与 await

async/await 是 ES2017 引入的异步编程语法，本质是 Promise 的语法糖，让异步代码具备同步代码的可读性，底层仍完全基于 Promise 和 JavaScript 事件循环机制；

### async 函数的返回值

调用 async 函数，永远返回一个 Promise 对象，具体状态与值遵循以下规则：

返回普通值： 函数内部 return 非 Promise 的普通值时，会自动包装为 `fulfilled`（已兑现）状态的 Promise，兑现值就是该返回值；

```
async function getValue() {
  return 42;
}

getValue().then(console.log); // 42
```

返回 Promise /thenable 对象：若内部 return 一个 Promise 或具有 `.then` 方法的 thenable 对象，外层 Promise 会跟随其最终状态；

注意：async 函数返回的始终是一个新的 Promise 实例，不保证与函数内部返回的 Promise 是同一个对象。

```
const innerReject = Promise.reject(new Error('内部出错'));

async function failAsync() {
  return innerReject;
}

failAsync().catch((err) => {
  console.log('外层捕获：', err.message); 
  // 输出：外层捕获： 内部出错
});
```

抛出异常：函数内部抛出错误时，返回的 Promise 会变为 `rejected`（已拒绝）状态，拒绝原因就是抛出的错误。

```
async function fail() {
  throw new Error("failed");
}
fail().catch(console.error); // Error: failed
```

### await执行机制

`await` 只暂停当前所在的 async 函数，不会阻塞整个 JavaScript 主线程，主线程会继续执行后续的同步代码；

当 `await` 右侧的 Promise 状态决定后，async 函数中 `await` 之后的代码会作为微任务加入队列，等待当前所有同步代码执行完毕后再执行；

```
async function run() {
  console.log("before");
  await Promise.resolve();
  console.log("after");
}

run();
console.log("outside");

// "before"、"outside"、"after"
```

`await` 后面可以是任意表达式，不局限于 Promise。如果是普通值，会被 `Promise.resolve()` 自动包装，后续代码依然是异步恢复；

```
async function run() {
  console.log(1);
  const value = await 2;
  console.log(value);
}

run();
console.log(3);

// 1、3、2
```

### 异常捕获

`await` 等待的 Promise 变为 rejected 时，会在 `await` 所在位置抛出异常，可以用 `try/catch` 块捕获；

```
async function loadData() {
  try {
    const response = await fetch("/api/data");
    // 注意：fetch 遇到 HTTP 404/500 不会自动 reject，需要手动判断状态
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    return await response.json();
  } catch (error) {
    console.error("load failed:", error);
    // 可选择吞掉错误，或重新抛出交给调用方处理
    throw error;
  }
}
```
