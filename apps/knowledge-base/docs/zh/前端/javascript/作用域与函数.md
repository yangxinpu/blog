## 作用域与变量绑定

### 作用域

JavaScript 的作用域（变量的有效访问范围）采用词法作用域，也叫静态作用域，变量查找、作用域范围由代码书写定义位置决定，和函数调用位置无关；函数在定义时就确定了作用域链，调用的时候只会沿用定义时的作用域链；

```
const name = "global";
function printName() {
  console.log(name); // 词法上的外层是全局作用域
}
function run() {
  const name = "local";
  printName(); // 调用位置不影响查找规则
}
run(); // 输出 "global"

// printName 定义在全局作用域，它的作用域链外层就是全局环境，因此无论在哪里调用，都会沿着定义时的作用域链查找，最终找到全局的 name；
```

按范围从大到小，JavaScript 共有 全局作用域、函数作用域、块级作用域、模块作用域 四种，不同变量声明受不同作用域约束；

**全局作用域**：最顶层的作用域，程序任何位置都能访问其中的变量，不同环境的全局对象会有差异：

- 浏览器环境：全局对象是 `window`；
- Node.js 环境：全局对象是 `global`；
- ES2020 引入 `globalThis`，统一跨环境的全局对象引用。

 隐式全局变量：非严格模式下，未声明直接赋值的变量会自动成为全局对象的属性（如 `a = 1` 等价于 `window.a = 1`），属于不良实践；严格模式下会直接抛出 `ReferenceError`；

**函数作用域**：由 `function` 声明创建的作用域，`var` 声明和函数声明仅在当前函数内部可见，外部无法直接访问：

- 函数形参也属于当前函数作用域；
- 早期 JS 只有全局和函数两种作用域，因此用立即执行函数表达式（IIFE） 来模拟块级作用域、避免全局污染；

**块级作用域（ES6 新增）**：由 `{ }` 包裹的代码块创建，`let`、`const`、`class` 声明仅在当前代码块内可见；常见的块级作用域场景：`if/else` 块、`for/while` 循环块、`try/catch` 块、单独的 `{}` 裸块，特点：

- `var` 不受块级作用域约束，会 “穿透” 块，泄露到外层的函数 / 全局作用域；
- `for` 循环中用 `let` 声明的循环变量，会为每一次迭代创建一个独立的块级作用域，每次迭代的变量都是全新的绑定；
- `catch (e)` 中的错误参数 `e` 属于 catch 块的块级作用域，外部不可访问

**模块作用域**：ES Module（ESM）天生具有独立的模块作用域，模块顶层的所有声明（`var`、`let`、`const`、函数、类）都只属于当前模块，不会泄露到全局，也不会自动挂载到全局对象，特点：

- ESM 顶层的 `this` 是 `undefined`，而经典脚本顶层 `this` 指向全局对象；
- 模块之间通过 `import` / `export` 显式交换变量，天然实现作用域隔离；
- Node.js 的 CommonJS 模块也有独立的模块作用域，顶层 `var` 不会成为全局变量。

### 变量提升与函数提升

“提升” 是描述 JS 执行行为的概念：在代码执行前，引擎会先扫描当前作用域的所有声明，建立变量绑定，看起来像是声明被 “移动” 到了作用域顶部，但源码本身不会被物理移动；

**var 的提升**：只有声明被提升，赋值语句留在原地执行， 同一作用域内多次 `var` 声明同名变量，后续声明会被忽略，赋值正常生效。

```
console.log(value); // undefined（声明已提升，未赋值）
var value = 10;
console.log(value); // 10
```

**函数声明的提升**：函数声明的整个定义（创建 + 初始化 + 赋值）都会被提升，因此在声明前调用可以正常执行；

注意：函数表达式不具备函数提升，而遵循 `var`或`let、const `的提升规则。

```
sayHello(); // "hello" 函数声明提升
function sayHello() { console.log("hello"); }

sayHi(); // TypeError: sayHi is not a function
var sayHi = function() { console.log("hi"); };
```

 **函数提升与 var 提升的优先级**：同一作用域中，函数声明的提升优先级高于 var 声明：

1. 先处理所有函数声明，完成完整绑定；
2. 再处理 `var` 声明，如果标识符已存在则忽略创建，保留函数值；
3. 执行到后续赋值语句时，变量值才会被覆盖。

```
console.log(typeof foo); // "function"，函数优先级更高
var foo = 10;
function foo() {}
console.log(foo); // 10，赋值语句覆盖了函数
```

### 暂时性死区

 `let`/`const`/`class` 从进入当前块级作用域开始，到声明语句执行之前，变量处于暂时性死区（Temporal Dead Zone），此区域内访问该变量会直接抛出 `ReferenceError`；

```
{
  // console.log(count); // ReferenceError
  const count = 1;
  console.log(count); // 1
}
```

### 作用域链

执行上下文：JS 代码执行时，引擎创建的环境，存放当前代码执行的相关信息。每个执行上下文都关联一个词法环境；

词法环境（LexicalEnvironment）：

- 保存当前作用域内所有标识符（变量、函数声明）的绑定
- 保存对外部词法环境的引用（指向外层）

作用域链：依靠词法环境里保存的外层引用，一层层嵌套形成的链条，就是作用域链；

当访问一个变量 / 函数时，JS 引擎会沿着作用域链从内到外逐级查找：

1. 先在当前作用域的词法环境中查找；
2. 找不到就进入外层词法环境继续查找；
3. 一直追溯到全局作用域；
4. 整条链上都找不到标识符，读取时抛出 `ReferenceError`，赋值时非严格模式创建隐式全局变量，严格模式报错；

```
const globalValue = 1;

function outer() {
  const outerValue = 2;

  function inner() {
    const innerValue = 3;
    return globalValue + outerValue + innerValue;
  }

  return inner();
}

outer(); // 6
```

## 函数

### 函数是一等对象

在 JavaScript 中，函数本质是可调用的对象，是 `Function` 构造函数的实例，拥有普通对象的全部能力，因此被称为 “一等公民”，可以：

1. 可以赋值给变量；
2. 可以作为函数参数传递；
3. 可以作为函数返回值；
4. 可以在运行时创建；
5. 可以拥有自己的属性；

```
// 示例：带缓存的阶乘函数
function factorial(n) {
  if (n <= 1) return 1;
  // 读取自身缓存
  if (factorial.cache[n]) return factorial.cache[n];
  const result = n * factorial(n - 1);
  factorial.cache[n] = result;
  return result;
}

factorial.cache = {}; // 给函数添加缓存属性
factorial(5); // 120，计算后缓存结果
factorial(5); // 120，直接读取缓存
```

### 函数参数

JavaScript 函数参数经历了从早期 `arguments` 到 ES6 剩余参数、默认参数、解构参数的演进，形成了灵活且强大的参数处理体系

#### arguments

arguments是非箭头函数内部自动生成的类数组对象，包含本次函数调用传入的所有实参；核心特性：

- 是类数组而非数组：拥有 `length` 属性和索引访问，但没有数组原型方法（`push`、`map` 等）；
- 与形参的映射关系：非严格模式下，`arguments` 和对应形参共享同一块内存，修改其中一个会同步修改另一个；而在严格模式下不存在映射关系，互相独立；

```
function printArguments() {
  console.log(arguments.length);
  console.log(arguments[0]);
}

printArguments("a", "b"); // 2、"a"
```


#### 剩余参数

ES6 引入剩余参数，作为 `arguments` 的现代化替代方案，专门用于接收未被具名形参匹配的剩余实参，核心规则：

- 语法为 `...参数名`，必须放在形参列表的最后一位，且一个函数只能声明一个剩余参数；
- 是真正的数组：剩余参数是标准的 Array 实例，可以直接使用所有数组方法（`map`、`reduce`、`filter` 等）；
- 箭头函数可以正常使用剩余参数，解决了箭头函数没有自身 `arguments` 的问题；

```
function sum(base, ...nums) {
  console.log(nums); // [2, 3, 4]，仅包含剩余的实参
  return base + nums.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3, 4); // 10
```

#### 默认参数

ES6 支持为函数形参设置默认值，当传入的实参为 `undefined` 时，自动使用默认值填充，核心特性：

- 只有当实参严格等于 `undefined` 时，才会触发默认参数；`null`、`0`、`''`、`false` 等 falsy 值都不会触发默认值；
- 函数的参数列表会形成一个独立的作用域，参数按照从左到右的顺序初始化，严格遵循暂时性死区（TDZ）规则，不能在初始化前互相引用；
- 默认值可以是任意表达式（函数调用、变量、运算等），表达式是在**函数调用时执行**，而非函数定义时执行，每次调用都会重新计算；

```
// 反例：参数 TDZ 报错
function fn(a = b, b = 1) {}
fn(); // ReferenceError: b is not defined

// 正确示例：对象解构 + 默认值
function createUser({ name = "匿名", age = 18 } = {}) {
  return { name, age };
}
createUser(); // { name: "匿名", age: 18 }
```

#### 参数解构

可以在形参位置直接对传入的对象或数组进行解构，将属性 / 元素提取为独立变量，配合默认值使用非常灵活；

```
// 对象解构参数
function printUser({ name, age = 18 }) {
  console.log(`${name}: ${age}岁`);
}

// 数组解构参数
function sum([a, b]) {
  return a + b;
}
```
### 箭头函数

ES6 引入的箭头函数（`=>`）不只是函数的简写语法，核心特性它没有自己的动态 this，而是在定义时从外层词法作用域捕获 this 并永久固定，这一特性解决了大量传统函数 this 指向混乱的问题，但也带来了一系列明确的使用限制；

对比：普通函数的 this 指向调用时的执行上下文，和定义位置无关，只和调用方式有关；

```
const double = (value) => value * 2;

const add = (a, b) => {
  return a + b;
};
```

箭头函数的特点：

- 没有自己的 `this`：`this` 指向定义时外层作用域的 `this`，且永久固定，`call`/`apply`/`bind` 都无法修改；
- 没有自己的 `arguments`：访问 `arguments` 会向上层作用域查找；需要可变参数用剩余参数替代；
- 没有 `super` 和 `new.target`：无法作为子类构造函数，无法检测是否被 `new` 调用；
- 不能通过 `new` 调用：没有 `[[Construct]]` 内部方法，`new` 调用会直接抛出 TypeError；
- 没有 `prototype` 属性：无法作为构造函数实现原型继承；
- 不能作为生成器函数：内部不能使用 `yield` 关键字；

```
const counter = {
  value: 0,
  start() {
    // 箭头函数创建时捕获 start 方法的 this（即 counter 对象）
    setTimeout(() => {
      this.value++;
      console.log(this.value);
    }, 0);
  }
};

counter.start(); // 1，this 正确指向 counter
```


### 立即执行函数

立即执行函数表达式（IIFE）在创建后立即调用，过去常用于创建私有作用域、避免污染全局；现代模块已经具有独立作用域，因此模块代码通常不再需要用 IIFE 隔离变量；

```
// 最常见：括号包裹函数声明，强制转为表达式
(function () {
  console.log("立即执行");
})();

// 变体：一元运算符强制转为表达式
!function () {}();
+function () {}();
~function () {}();

// 传参 IIFE
(function (window, undefined) {
  // 内部使用局部 window 和 undefined，防止全局污染，便于压缩
})(window);
```

### 闭包

闭包是函数与其声明时词法环境的组合；闭包可以访问外层作用域的所有变量，即使外层函数已经执行完毕、执行上下文已销毁，词法环境仍会因为闭包的引用而保留；

闭包保存的是变量绑定的引用，不是创建时的值快照；

闭包本身不会造成内存泄漏，是闭包长期持有大对象引用、且不再使用时未释放才会导致内存无法回收；比如，全局事件回调、定时器引用了大型 DOM 对象或数据，页面卸载前未移除监听；

```
let count = 1;
function getCount() {
  return count; // 闭包引用变量本身，不是值
}

count = 2;
getCount(); // 2，读取到最新的绑定值
```

## this

`this` 是 JavaScript 函数在执行时自动生成的隐式上下文参数，代表当前函数的调用上下文；

对于普通函数，this 是函数调用时动态绑定的隐式参数，完全由调用方式（调用点）决定，与函数定义位置、所属对象无关；而箭头函数不遵循动态绑定规则，它的 this 在定义时就从外层词法作用域捕获并永久固定；

按照优先级从低到高，普通函数的 this 绑定分为默认绑定、隐式绑定、显式绑定、new 绑定四类；

### 默认绑定

当函数被独立直接调用（没有点号、没有 call/apply、没有 new）时触发，核心规则：

- 非严格模式：`this` 指向全局对象（浏览器环境为 `window`，Node.js CommonJS 环境为 `global`）。
- 严格模式：`this` 为 `undefined`。

```
// 非严格模式
function fn1() {
  console.log(this); // 浏览器中为 window
}
fn1();

// 严格模式
'use strict';
function fn2() {
  console.log(this); // undefined
}
fn2();
```
### 隐式绑定

函数通过对象属性调用的形式执行，即 `obj.fn()` 时，触发隐式绑定；点号左侧的对象会被绑定为本次调用的 this。如果是链式调用 `obj1.obj2.fn()`，this 指向最后一个点号左侧的对象（`obj2`）；

```
const user = {
  name: "Alice",
  printName() {
    console.log(this.name);
  }
};

user.printName(); // "Alice"，this 指向 user

// 链式调用
const admin = {
  user: user,
  role: "admin"
};
admin.user.printName(); // "Alice"，this 指向 admin.user
```

隐式绑定丢失：当普通函数从对象中取出后再独立调用，会丢失原来的隐式绑定，退化为默认绑定；

```
const user = {
  name: "Alice",
  printName() {
    console.log(this.name);
  }
};

const print = user.printName;
print(); 
// 非严格模式：this 指向 window，打印 undefined 
// 严格模式：this 为 undefined，直接抛出 TypeError
```

### 显式绑定

通过 `call()`、`apply()`、`bind()` 三个方法手动指定函数调用的 this 指向，优先级高于隐式绑定和默认绑定；

| 方法                             | 执行时机  | 参数形式          | 返回值        |
| ------------------------------ | ----- | ------------- | ---------- |
| `call(thisArg, arg1, arg2...)` | 立即执行  | 参数逐个传入        | 原函数执行结果    |
| `apply(thisArg, argsArray)`    | 立即执行  | 参数以数组 / 类数组传入 | 原函数执行结果    |
| `bind(thisArg, arg1, arg2...)` | 不立即执行 | 可预设部分参数       | 返回一个新的绑定函数 |

当传入 `null`、`undefined` 或原始值作为 thisArg 时，绑定规则会有差异：

1. 传入 null /undefined：
    - 严格模式：`this` 严格等于传入的 `null` / `undefined`；
    - 非严格模式：会被自动替换为全局对象（浏览器 `window`）。
2. 传入数字、字符串、布尔等原始值：
    - 严格模式：`this` 就是原始值本身；
    - 非严格模式：会自动装箱为对应包装对象（如 `1` → `new Number(1)`）

```
function introduce(greeting, punctuation) {
  return `${greeting}, ${this.name}${punctuation}`;
}

const user = { name: "Alice" };

// call：逐个传参
console.log(introduce.call(user, "Hello", "!")); 
// "Hello, Alice!"

// apply：数组传参
console.log(introduce.apply(user, ["Hello", "!"])); 
// "Hello, Alice!"

// bind：返回新函数，支持偏函数传参
const boundIntroduce = introduce.bind(user, "Hello");
console.log(boundIntroduce("!")); 
// "Hello, Alice!"
```

### new 绑定

使用 `new` 关键字调用构造函数时，函数内部的 this 指向新创建的实例对象，这是优先级最高的绑定方式；

```
function User(name) {
  this.name = name;
  // 没有 return，默认返回新对象
}

const user = new User("Alice");
console.log(user.name); // "Alice"
```
