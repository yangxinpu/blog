## 异常处理

在 JavaScript 中，异常处理是保证程序健壮性的核心机制，用于捕获和处理程序运行中出现的非预期错误，避免程序直接崩溃；
### Error 对象

`Error` 是 JavaScript 中所有错误的基类，用于封装错误的类型、描述、调用栈等信息，是异常处理的核心载体，核心属性：

- `name`：错误类型的名称，默认值为 `"Error"`，错误子类会对应修改（如 `"SyntaxError"`）；
- `message`：人类可读的错误描述信息，对应构造函数的第一个入参；
- `stack`：错误发生时的**调用栈追踪信息**，包含错误出现的位置、完整调用链，格式由运行环境（浏览器 / Node.js）决定；
- `cause`：可选，用于标记**错误的底层原因**，形成错误链，方便追溯最原始的错误源；

```
// 基础用法
const basicError = new Error("请求失败");

// 带 cause 的错误链：外层业务错误包装底层技术错误
const error = new Error("Request failed", {
  cause: new Error("Network unavailable") // 原始底层错误：网络不可用
});

console.log(error.message); // "Request failed"
console.log(error.cause);   // Error: Network unavailable（完整的原始错误对象）
console.log(error.stack);   // 完整调用栈信息，用于定位错误位置
```

### throw

`throw` 语句用于主动抛出一个异常，中断当前代码的执行，跳转到最近的 `catch` 捕获逻辑；如果没有任何捕获逻辑，则会导致程序全局崩溃；

```
function divide(a, b) {
  if (b === 0) {
    throw new RangeError("Divisor cannot be zero");
  }
  return a / b;
}
```

### try、catch 与 finally

这是 JavaScript 最基础的异常捕获结构，用于包裹可能出错的代码，并对错误进行兜底处理：

1. try 块：放入可能抛出异常的代码，按顺序同步执行；
2. catch 块：当 try 内抛出异常时，try 内后续代码中断，直接跳转到 catch，参数为抛出的错误对象；如果没有错误，catch 块不执行；
3. finally 块：无论 try 成功执行、还是 catch 捕获到错误，finally 块一定会执行，通常用于资源清理（关闭连接、清空定时器、释放锁等）；

```
try {
  // 可能出错的代码
  const data = JSON.parse("{");
  console.log(data);
} catch (error) {
  // 处理错误
  console.error("解析失败：", error.message);
} finally {
  // 无论成功失败都执行
  console.log("解析流程结束");
}
```

如果不需要访问错误对象本身，可以省略 catch 的参数

```
try {
  JSON.parse("{");
} catch {
  console.log("Invalid JSON");
}
```

不要在 finally 中使用 `return`、`throw`、`break` 或 `continue`，这些控制流语句会覆盖 try 或 catch 中的返回值 / 抛出的错误，是非常经典的语法坑；

```
function example() {
  try {
    return 1; // 本来要返回 1
  } finally {
    return 2; // finally 的 return 会覆盖前面的所有结果
  }
}
example(); // 返回 2，而不是 1
```

### 同步错误与异步错误

`try...catch` 有一个核心限制：只能捕获当前同步调用栈中抛出的错误，对于异步回调中的错误，它无法捕获；

```
try {
  setTimeout(() => {
    throw new Error("async error");
  }, 0);
} catch {
  // 无法捕获定时器回调之后抛出的错误
}
```

Promise 链式调用中，reject状态会沿着链向后传递，直到遇到最近的 `.catch()`。

```
fetch("/api/user")
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((error) => {
    // 捕获前面所有 then 中出现的错误
    console.error("请求失败：", error);
  });
```

`await` 会暂停当前函数，等待 Promise 状态变更；当 Promise 拒绝时，相当于在 await 位置抛出异常，可以被外层 `try...catch` 捕获。这是最推荐的异步错误写法，逻辑最清晰

```
async function loadUser() {
  try {
    const response = await fetch("/api/user");
    return await response.json();
  } catch (error) {
    console.error("加载用户失败：", error);
    // 可以选择内部消化错误，或者继续向上抛出
    throw error;
  }
}
```

### 自定义错误

在业务开发中，内置错误类型不足以描述业务场景（如参数校验失败、权限不足、业务状态异常等），我们可以通过继承 `Error` 类来自定义错误，携带业务专属信息；

```
class ValidationError extends Error {
  /**
   * @param {string} message 错误描述
   * @param {string} field 校验失败的字段名
   * @param {object} options 其他配置（如 cause）
   */
  constructor(message, field, options) {
    // 调用父类构造函数，传递 message 和 options
    super(message, options);
    // 必须手动设置 name，否则继承后 name 仍为默认的 "Error"
    this.name = "ValidationError";
    // 自定义属性：标记校验失败的字段
    this.field = field;
  }
}

// 使用示例
function validateUser(user) {
  if (!user.name) {
    throw new ValidationError("Name is required", "name");
  }
}

// 分类捕获处理
try {
  validateUser({});
} catch (error) {
  if (error instanceof ValidationError) {
    console.error(`字段 ${error.field} 校验失败：${error.message}`);
  } else {
    console.error("未知错误：", error);
  }
}
```
