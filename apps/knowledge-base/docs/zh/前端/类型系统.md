## JavaScript 类型系统

### 原始类型与对象类型

JavaScript 一共有 8 种数据类型，其中包含 7 种原始类型，剩下 1 种为对象类型：

- 原始类型：`undefined`、`null`、`boolean`、`number`、`bigint`、`string`、`symbol`；
- 对象类型：普通对象、数组、函数、日期、正则表达式、Map、Set 等都归属于对象类型，函数属于可调用对象，不过使用`typeof function () {}`检测时，返回结果为`"function"`；

原始类型的值是不可改变的，比如调用字符串的方法，并不会修改原本的字符串，只会返回一个新的字符串；而对象内部的属性是可以被修改的，但是引用不会改变；

```
let text = "hello";
text.toUpperCase();
console.log(text); // "hello"

const user = { name: "Alice" };
user.name = "Bob";
console.log(user.name); // "Bob"
```

### typeof 

`typeof`适合用来判断原始类型与函数，但无法精准区分不同种类的对象

```
typeof undefined; // "undefined"
typeof true; // "boolean"
typeof 1; // "number"
typeof 1n; // "bigint"
typeof "text"; // "string"
typeof Symbol("id"); // "symbol"
typeof function () {}; // "function"

typeof null; // "object"
typeof []; // "object"
typeof {}; // "object"
```

`typeof null === "object"` 是 JavaScript 早期实现遗留的结果，不能据此把 `null` 当成对象；

想要更精确判断类型，可以使用别的方法：

```
Array.isArray([]); // true

Object.prototype.toString.call(new Date()); // "[object Date]"
```

### undefined 与 null

`undefined`代表未赋值的状态，产生的场景有： 声明了但没有赋值的变量、没有 return 返回值的函数、读取对象不存在的属性、函数调用时未传入的参数；

`null`是开发者手动赋值使用，代表主动设置为空、空对象引用；

```
let result;
console.log(result); // undefined

const selectedUser = null;
```

两者对比：

```
null == undefined; // true，抽象相等规则中的特例
null === undefined; // false
```

### 特殊Number
#### NaN 

`NaN` 表示某次数值运算没有得到有效数字，它本身仍属于 `number` 类型；

```
typeof NaN; // "number"
Number("hello"); // NaN
0 / 0; // NaN
```

`NaN` 与任何值都不相等，包括它自身；所以判断`NaN`推荐使用`Number.isNaN()`；

```
NaN === NaN; // false

Number.isNaN(NaN); // true
```

#### Infinity

`Infinity`与`-Infinity`分别代表正无穷和负无穷，二者都属于`number`类型

`Number.MIN_VALUE`是无限趋近于 0 的最小正数，但并不是最小负数；

可以通过`Number.MIN_SAFE_INTEGER`、`Number.MAX_SAFE_INTEGER`获取安全整数的上下限；

```
1 / 0; // Infinity
-1 / 0; // -Infinity
Number.MAX_VALUE * 2; // Infinity

Number.isFinite(10); // true
Number.isFinite(Infinity); // false
Number.isFinite("10"); // false
```

`Number.isFinite`只有在参数是有限数字时才返回 true，不会自动做类型转换，传入字符串直接返回 false；

### Symbol

`Symbol` 用于创建唯一的原始值，常用作对象的属性名，用来避免和普通字符串属性名产生冲突；

`Symbol` 通过Symbol构造函数传入描述文本来创建；其中，描述文本只用于调试，不参与Symbol值的相等比较；

```
const first = Symbol("id");
const second = Symbol("id");

first === second; // false

const user = {
  [first]: 1001,
};

console.log(user[first]); // 1001
```

Symbol 类型的属性键不会被`Object.keys()`、`for...in`遍历到，也不会被JSON 序列化。想要获取对象上的 Symbol 属性，可以使用`Object.getOwnPropertySymbols()`或者`Reflect.ownKeys()`。

```
const token = Symbol("token");
const data = {
  visible: true,
  [token]: "secret",
};

Object.keys(data); // ["visible"]
Object.getOwnPropertySymbols(data); // [token]
Reflect.ownKeys(data); // ["visible", token]
```

`Symbol.for()`会访问全局 Symbol 注册表，传入相同的 key，拿到的是同一个 Symbol；而`Symbol.keyFor()`用来读取全局注册的 key。

普通`Symbol()`创建的值不会存入全局注册表，使用`Symbol.keyFor`获取会返回`undefined`

```
const key1 = Symbol.for("app.user");
const key2 = Symbol.for("app.user");

key1 === key2; // true
Symbol.keyFor(key1); // "app.user"
Symbol.keyFor(Symbol("app.user")); // undefined
```

### BigInt

`BigInt` 用于表示任意精度整数，适合用来处理超出安全整数范围的整数，通过字面量以 `n` 结尾或者BigInt构造函数创建；

核心规则：

- 不能与 Number 直接进行算术运算；
- 可以与 Number 比较，但严格相等时类型不同；
- 除法只保留整数部分；
- 不支持大多数 `Math` 方法；
- 默认不能被 `JSON.stringify()` 序列化；

```
const first = 9007199254740993n;

const second = BigInt("9007199254740993");

first === second; // true

1n + 2n; // 3n
5n / 2n; // 2n
1n < 2; // true
1n === 1; // false

// 1n + 1; // TypeError
```

序列化 BigInt 时需要自定义转换规则。不能简单只用数字字符串还原，避免普通字符串被错误转换成 BigInt；可以把 BigInt 转为带 type 标记的对象再序列化：

```
const json = JSON.stringify(
  { id: 9007199254740993n },
  (key, value) =>
    typeof value === "bigint"
      ? { type: "bigint", value: value.toString() }
      : value,
);

const data = JSON.parse(json, (key, value) => {
  if (value?.type === "bigint") {
    return BigInt(value.value);
  }
  return value;
});
```


## 类型转换与比较

### 装箱

装箱：原始值临时转换为对应包装对象的过程，目的是让原始值能够使用包装对象原型上的属性和方法

现代 JS 引擎（如 V8、JavaScriptCore）会对这个过程做优化，不会真实创建堆对象，而是直接在底层调用对应逻辑，避免了对象分配的性能开销；

```
const text = "hello";

text.length; // 5
text.toUpperCase(); // "HELLO"
```

注意：所有包装对象都是引用类型，因此在布尔转换中全部为 `true`，哪怕包装的是 falsy 值：

```
const wrappedFalse = new Boolean(false);
if (wrappedFalse) {
  console.log("这段代码会执行！"); // 对象恒为 truthy
}

Boolean(wrappedFalse);       // true
Boolean(wrappedFalse.valueOf()); // false，手动拆箱后才是原始值
```

### 拆箱

对象转为原始值的过程叫做拆箱，底层依靠 JS 内部抽象操作 `ToPrimitive`，也是对象参与运算、比较的基础；

`ToPrimitive(input, hint)` 是引擎内置方法，专门用来把对象转换成原始类型。当对象参与字符串、数字运算或者部分比较操作时，就会触发这个过程；

执行优先级：

1. 如果对象上存在 `obj[Symbol.toPrimitive]`，优先调用该方法；
2. 不存在时，根据 hint 的提示，依次尝试调用 `valueOf()`、`toString()`；
3. 若最终拿不到原始值，抛出 `TypeError`；

对普通对象而言，ToPrimitive 的方法的hint决定遵循下面规则：

- 当执行 `Number(obj)`、一元加号 `+obj`、减乘除算术运算、`>` / `<` 大小比较操作时，hint 为 `"number"`：优先调用 `valueOf()`，如果得不到原始值，再调用 `toString()`。
- 当执行 `String(obj)`，或是对象作为属性键（如 `obj[someObj]`）时，hint 为 `"string"`：优先调用 `toString()`，得不到原始值的情况下，再调用 `valueOf()`。
- hint 取值为 `"default"` 时：绝大多数普通对象会按照 hint 为 `"number"` 的逻辑处理；Date 对象是特例，会按照 hint 为 `"string"` 的逻辑处理

我们可以重写 `Symbol.toPrimitive` 自定义拆箱逻辑，该方法必须返回原始值，否则会报错：

```
const price = {
  amount: 42,

  [Symbol.toPrimitive](hint) {
    if (hint === "string") {
      return `¥${this.amount}`;
    }
    return this.amount;
  },
};

Number(price); // 42
String(price); // "¥42"
price + 8; // 50
```

### ToNumber

`Number()`、一元加号 `+x`、减法 / 乘法 / 除法 / 取余等算术运算，都会触发ToNumber数字转换；

各类型值进行 ToNumber 数值转换的结果：

- `undefined` → `NaN`
- `null` → `0`
- Boolean：`true → 1`，`false → 0`
- String：
    - 空串 `""` 或空白字符串（`" "`、`"\t\n"`）→ `0`
    - 能解析为数字的字符串（`"123"`、`"-3.14"`）→ 对应数字
    - 不能解析为数字的字符串（`"abc"`、`"12a"`）→ `NaN`
- 对象：执行ToPrimitive( hint=number)，得到原始值后再 ToNumber

```
Number("  0b101  "); // 5（支持二进制字面量）
Number("12px");      // NaN（中间含非法字符）
Number([]);          // 0 → []→valueOf()返回数组(忽略)→toString()返回""→转0
Number([123]);       // 123 → [123].toString() → "123" → 123
Number([1,2]);       // NaN → toString 得到 "1,2" 无法转数字
Number({});          // NaN → toString 得到 "[object Object]" 无法转数字
```

### ToString

 `String(value)`、模板字符串、字符串拼接，都会触发 ToString 字符串转换；但三者对对象调用 ToPrimitive 时使用的 hint 不同：

- `String(obj)` 和模板字符串：底层走 ToString 抽象操作，对对象调用 `ToPrimitive(hint=string)`，优先尝试 `toString()`，得不到原始值再尝试 `valueOf()`；
- `obj + "str"` 字符串拼接：`+` 运算符不传 hint，对对象调用 `ToPrimitive(hint=default)`，普通对象按 `"number"` 逻辑处理（优先 `valueOf()`，再 `toString()`），Date 对象按 `"string"` 逻辑处理。

如果输入是对象，则会先执行对应 hint 的 ToPrimitive 拆箱获取原始值，再将这个原始值转为字符串：

- 空数组转化过程（hint=string）：`[].toString()` → `""`（已是原始值，不再调用 valueOf），ToString → 还是 `""`；
- 空对象转化过程（hint=string）：`{}.toString()` → `"[object Object]"`（已是原始值，不再调用 valueOf），ToString 结果还是 `"[object Object]"`

```
String(undefined); // "undefined"
String(null); // "null"
String(true); // "true"
String(12); // "12"
String(10n); // "10"
String(Symbol("id")); // "Symbol(id)"
```

特殊规则：使用`String()`显式转换 Symbol 是被允许的；但隐式字符串拼接时，底层抽象操作 ToString 碰到 Symbol 会直接抛出错误，而`String`构造函数单独对 Symbol 做了兼容处理；

```
String(Symbol("id")); // "Symbol(id)"

// "" + Symbol("id"); // TypeError
```

### ToBoolean

`if`、`while`、`for` 的判断条件，三元表达式条件，`!`、`&&`、`||` 逻辑运算，双重否定 `!!` 以及 `Boolean` 构造函数，都会触发 ToBoolean 布尔转换；

布尔转换规则很简单：

- 只有 `false`、`0`、`-0`、`0n`、`NaN`、空字符串`""`、`null`、`undefined` 这八个值会转为 `false`；
- 其余全部都是真值，例如 `"0"`、`"false"`、空数组`[]`、空对象`{}`。

对象不会执行 valueOf、toString 或者 Symbol.toPrimitive 拆箱，所有对象直接转为 true；

```
Boolean(0); // false
Boolean("hello"); // true

Boolean("0"); // true
Boolean([]); // true
Boolean({}); // true
```

### `==`、`===` 与 Object.is

严格相等 `===` 不会进行任何类型转换，两个值类型不一样就直接返回 false：

```
1 === "1"; // false
NaN === NaN; // false
0 === -0; // true
```

抽象相等 `==` 在类型不同时会发生隐式类型转换才进行比较，常见规则包括：

- `null` 只与 `undefined` 抽象相等；
- 布尔值参与比较：Boolean 会先转成 Number：`true → 1`，`false → 0`；
- String 和 Number 比较：String 转 Number，不能转得到 `NaN`，NaN == 任何东西永远false；
- 对象与原始值比较：对象先执行 ToPrimitive(hint=default)（普通对象按 number 逻辑优先 valueOf，Date 对象按 string 逻辑优先 toString），拿到原始值之后再继续上面的规则；

```
// 步骤：false转Number→0；[]执行ToPrimitive→""；""转Number→0；
[] == false; // true

// 步骤：![] 先执行→!true→false；变成 [] == false，后续和上面一致 
[] == ![]; // true

// 步骤：null只和undefined相等，不参与数值转换
null == 0; // false

// 步骤：true转1；"1"转1；
"1" == true; // true
```

`Object.is()` 与 === 几乎完全一致，仅修正了两个反直觉的边界情况：

-  `NaN` 与自身比较视为相等，
- `0` 和 `-0`不相等；

```
Object.is(NaN, NaN); // true
Object.is(0, -0); // false
```

### 关系运算符的转换规则

关系运算符`<`、`>`、`<=`、`>=` 隐式转化逻辑和抽象相等 `==`不一样，规则为：

- 如果有对象，则先进行ToPrimitive(hint=number)拆箱得到原始值；
- 两边都是字符串：按 UTF-16 码元，逐字符字典序比较，不转数字；
- 其他任意情况：两个值都执行 `ToNumber` 转为数字，再比较数值大小；
- 若转换后任意一方是 NaN，`< > <= >=` 的结果一律为 false


```
"20" < "3";   // true
// 转换后两边都是字符串，字典序：字符'2'编码 < '3'

"20" < 3;     // false
// 一侧是数字，不是双字符串，"20"转数字20；20 < 3 → false

[2] < 3;      // true
// [2] ToPrimitive得到"2"，然后转数字2；2 < 3 → true

NaN < 5;      // false
NaN >= 5;     // false
NaN > 5;      // false
NaN <= 5;     // false
// 只要存在NaN，关系比较全部返回false
```

null的关系比较

```
null > 0;   // false
// 关系运算：null ToNumber → 0，0 > 0 → false

null == 0;  // false
// ==抽象相等规则：null仅与undefined相等，**不会转为数字**

null >= 0;  // true
// 关系运算：null ToNumber → 0，0 >= 0 → true
```
